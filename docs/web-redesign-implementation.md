# Web 方向 C 与授权 v2 实施说明

生产前端保持原生 TypeScript + DOM，没有新增运行时依赖。`web/app.ts` 管理聊天、同步、媒体与页面框架；`web/console.ts` 管理控制台表单和本地草稿。两个文件以普通脚本按顺序加载，共用类型和状态。构建为两个脚本分别添加内容哈希，并列入 Service Worker 清单；原型目录不参与发布。

## 已实现

- 以聊天为主界面，控制台、资料、日期、菜单、快速跳转和对话框按需打开。保留规格要求的元素 ID。
- 黑白灰与紫色令牌、系统/手动主题、容器断点、64px 会话列表、手机 list/thread 切换及安全区。
- 平铺消息、连续发送人分组、消息工具、回应、历史滚动加载与浮动提示；原有 IndexedDB、durable sync、重连、媒体解析和图片发送状态机继续使用。
- 12 个权限点、内置及自定义角色、个人覆盖、Steam 分级授权、指定好友及有效期，同时在 HTTP、WebSocket 和发送过程回调中检查。
- 控制台的 Steam 账户、用户四标签、角色与权限矩阵、审计字段差异、图片表情及设置。管理表单使用可聚焦的弹窗；权限和授权修改先保留为草稿。
- 登录、初始化、强制改密和启动重试；登录错误的剩余次数由后端计算。

## 实现决定

“退出其他设备”调用 `POST /api/auth/logout-all`，请求体为 `{ "keepCurrentSession": true }`，保留当前 Cookie 与会话。省略参数时继续撤销所有会话，兼容已有客户端。

非超级管理员分配 Steam 授权时，等级、好友范围及有效期都不能超过自身授权，避免通过自授权或转授扩大访问范围。`steam.account.all` 仍按规格提供完整授权。

指定好友用户的会话分页游标用 AES-256-GCM 封装，并绑定用户和活动账户。过滤后为空的页面不会暴露底层索引键中的其他好友 ID 或时间。令牌只用于遍历当前服务进程中的会话列表；服务重启后应重新加载列表，历史/同步游标的存储契约保持原样。

Steam 状态附带 `accessRevision`，根据等级、完整好友名单和有效期计算。IndexedDB 快照绑定此版本，因此人数相同的好友替换也不会恢复旧范围的消息；旧服务器未提供此版本时，指定好友授权不读取或写入本地快照。

`POST /api/users/:id/unlock` 用于用户页解除登录锁定，要求 `user.manage`，保护超级管理员并写入字段级审计。会话列表返回 `current` 标记当前设备。

## 发布

**发布前备份 `auth.db`。** 首次启动会在事务中执行授权 v2 迁移：旧 `admin/user` 转为 `super/member`，旧 Steam 授权转为完整、全部会话、永久。旧 `role` 字段继续输出给 Android 和旧客户端；迁移不能通过回滚程序二进制撤销。

真实 Steam 扫码、手机确认、密码/Guard 和实际媒体发送需要可用的 Steam 账户完成发布前人工验收。自动化测试使用模拟传输，并覆盖已安装 SDK 的发送重试与提交阶段授权重查。
